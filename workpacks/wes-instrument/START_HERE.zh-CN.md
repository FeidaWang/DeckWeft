# 从这里开始

## 这次交付的是什么
这是可以实际解压、检查、逐阶段交给 Codex 执行的工程工作包。不是“继续等待的研究任务”，也不是已经部署的幻灯片软件。

你要求的五个文件均已提供：`MASTER_PLAN.md`、`ARCHITECTURE.md`、`DESIGN_SYSTEM.md`、`PALETTES.json`、`TASKS.md`。另有 `AGENTS.md`、`TASKS.json`、七份阶段指令、研究纠错记录、来源登记、截图取色审计、可运行的参考函数与测试。

## 如何使用
1. 在你的电脑中打开现有的 DeckWeft 仓库文件夹。
2. 新建 `workpacks/wes-instrument/`，将本包内部所有内容放入其中。不要把本包文件覆盖到仓库根目录。
3. 在 Codex 中打开该仓库，复制 `prompts/START.md` 的全文。
4. Codex 先执行 `PHASE_00.md`：核查当前分支、既有实现与真实测试状态，再继续阶段 01–06。

无需你先理解 PowerPoint，也不需要接入新的付费 AI 服务。此工作包本身不会调用模型、购买服务、发布仓库或改变你的宿主权限。

## 本地检查
在工作包目录运行：
```sh
npm run verify
```
需要 Node.js 22 或更新版本；这些检查不需要 `npm install`。

双击 `palette-catalog.html` 可看配色数据。它是离线目录页，不是完整工作台。

## 必须知道的三件事
**调色盘不等于电影官方色卡。** 已登记 22 组社区色库配色，其中 16 组与上传截图标签对应。截图的 76 个采样色块中只有 1 个与色库 HEX 完全相同；因此同时保留截图采样值和色库原值，不混为一谈。没有电影帧和时码的条目不会写成“电影原色已验证”。

**原研究报告不等于可运行代码。** 原报告的示例命令、色值和引用存在待核验内容，已在 `RESEARCH_AUDIT.md` 中逐条处理，原文单独归档而不是当作执行规范。

**工作包测试不等于产品验收。** 本包的检查结果只证明本包结构、参考函数和数据检查通过。没有修改或推送你的 GitHub 仓库，没有在 PowerPoint、Keynote 或你的 Codex 客户端里执行产品验收。

## 阶段顺序
00 核验基线 → 01 配色与证据 → 02 文档输入与论点结构 → 03 排版和可编辑导出 → 04 极简工作台与旋钮 → 05 宿主适配及研究扩展 → 06 真实验收和发布准备。

任何阶段失败都要给出实际错误与恢复办法。不能用“任务已提交”“报告已生成”“本地模拟通过”代替真实交付。
