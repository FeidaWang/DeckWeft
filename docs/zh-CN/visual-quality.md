# 浏览器质量检查与有界修复

[English](../en/visual-quality.md) · [证据](../evidence/vis-010/review.md)

1. 使用 Node 22+ 和单独安装的 Playwright 测试模块。`CHROMIUM_PATH` 指向 `/Applications` 以外的独立测试浏览器，`PLAYWRIGHT_MODULE` 指向模块文件。已安装浏览器及个人配置保持只读。这些测试工具不属于运行依赖。
2. 运行 `npm run visual:verify -- --case release-gallery`。生成中英文、三种交互主题共六套 15 页完整故事。原封面、证据页和章节页保留作者主题。此代表样例不等于完整发布图库或宿主验收。
3. 运行 `npm run visual:review`，打开终端给出的回环地址。选择交互 HTML，打开整稿联系表、原尺寸场景截图及交互后状态。结果保存在 `dist/visual-quality`；不会调用远程服务、模型或图片服务。
4. 查看 `report.json`：包括逐区域文本／来源覆盖、精确图表值、实际平台字体、图片解码、控制台诊断、操作前后轨迹及结构化问题。边界框使用对应视口的文档 CSS 像素；全局错误或缺失几何明确记录为 null。来源覆盖仅表示原引用仍可访问，不判断引用真实性。裁切、对比度依据当前 DOM/SVG；连续超过三页使用同一构图契约会触发重复检查。细微构图重复仍需视觉判断。
5. 实际查看图像。联系表用于整稿节奏，原尺寸组件用于可读性，整稿长截图用于阅读顺序与响应式布局。哈希、DOM 通过或生成截图不能代替视觉审阅。
6. 将审阅对象数组另存为 JSON。每项需有 `receiptId`、`reviewer`、`delivery`（实际图像如何送达）、`images`（确实查看的文件名）、`judgment`、`issues` 和 `verdict`（`pass` 或 `fail`）。标为 `reviewRequired` 的图像必须查看，其余原尺寸场景可继续检查。视觉问题需包含 `sceneId`、`nodeId`、`bounds`、`severity`、`reason`、`suggestion`。证据目录中的审阅文件可作为格式示例。
7. 运行 `npm run visual:verify -- --review /绝对路径/review.json`。机器检查和当前图像审阅均通过才会通过质量门槛。写入审阅前会核对源代码／契约／主题／验证工具、输出和截图字节。自定义项目文件的变化也会使回执失效。

检查自有 v3 项目时使用 `--project /绝对路径/project.json --home /绝对路径/本地库`。v1/v2 仍使用独立渲染和存储路径，工具不会静默迁移或修补。内容、数据、来源、布局、素材、视口、交互状态或渲染器变化后应重新检查。`receiptCurrent` 比较项目及实际观测；回执仅适用于已记录状态，不能覆盖未来所有探索。新的状态需重新捕获。审阅声明是可追责记录，无法从技术上证明审阅者确实看过图像。

自动修复范围仅为受影响场景的构图。原文、数据、来源、素材、稳定身份、裁切及无关场景保持原样，并执行作者构图锁。对比度、来源、缺失素材和失效交互会停止自动修复，保留问题供明确的局部修复；不会补造内容、解锁或将整页栅格化。

默认每套稿最多 **两轮、六个实测候选、两处接受的场景变更、60,000 毫秒**。可用 `--max-rounds`、`--max-candidates`、`--max-scene-changes`、`--max-ms` 缩减预算；超过两轮会被拒绝。控制器拒绝超时结果并发送取消信号，外部评估器应响应取消信号及时释放资源。超时或不完整候选不会被提升为有效产物。流程结束或失败会关闭浏览器，耗时与拒绝原因留在报告中。

门槛失败时，查看 `repair.candidate`、`repair.attempts`、诊断及待审阅状态。候选 HTML 仍保留。新捕获前会把此前通过的产物复制到 `accepted/<receipt-id>/`；修复失败时 `repair.artifact` 指向该产物。若没有此前通过的产物，会明确报告并保留输入源。流程不会写入用户库、绕过修订冲突或修改历史。需要恢复内容时使用正常历史浏览器，再重新捕获；保留证据目录以保存旧回执和截图。

代表检查覆盖三种宽度 390/1024/1440 CSS 像素、减少动态效果、图表过滤、图解／代码步骤、图像比较／热点、重播／定位、键盘和原生触摸事件。此结果不等于全部辅助功能、浏览器引擎、字体环境、宿主或原生导出认证。原尺寸场景与 HTML 保持可编辑 DOM/SVG，只有质量联系表使用截图缩略图。
