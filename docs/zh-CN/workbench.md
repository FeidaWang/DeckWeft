# Visual Studio 工作台

[English](../en/workbench.md) · [任务工具](task-loop.md) · [宿主](hosts.md) · [证据](../evidence/vis-013/review.md)

## 先看作品

打开已保存的文稿，首先显示页面。左侧页面条使用同一份派生页面的非交互视图，显示真实图片和图表。选择缩略图，或在页面条上用方向键。**词**和**样子**在页面旁边（窄于 1050 px 或在手机上，**编辑**会把它们作为面板打开）。其余都在顶部的**更多**或**带走**里；一次只打开一个对话框，关闭后未保存的修改仍保留。

本地模式只排版所提供的原文：页与页之间空一行；一页原文保持一页。它不会研究主题、改写文字，也不会为凑页数重复页面。Codex 需要在**更多 → 让助手帮我写**（“按提示来写”）中明确选择，其操作许可也只在那里出现。

1. 运行 `node bin/deckweft.mjs studio --open`，打开打印的本地地址：视觉文稿和经典文稿在同一个地址打开，在**更多 → 备份与还原 → 我的文稿**里选另一种类型的文稿会就地切换，不刷新页面。
2. 没有打开文稿时，页面显示首次使用的粘贴框。粘贴你要讲的话（页与页之间空一行）后点**排好**，或点**先看个例子**。预期：得到一份原文逐字不变的普通 v3 文稿，并显示下面的三个方向。不会运行任何模型。
3. 要根据需求起草，打开**更多 → 让助手帮我写**。输入演示要讲什么，可选本地 `.txt`／`.md` 来源（最多 12,000 字符）和“受众”。选择“只排你的文字”或 Codex，再点“排版所提供文字”或“使用／继续所选文稿”。所提供的文字和数字保持原样；这里不实现任意 PDF／Office 导入。
4. 使用 Codex 时，勾选该次操作的许可。它使用已有宿主配置，可能消耗额度。不会登录，不会选择其他模型或服务商，也不会推断计费。Claude 仍然延后。
5. 同一节里的“草稿的样子”包含视觉风格、色彩强度、图像比重和更新偏好，并可选“应用到”仅选定页或整个项目。单页选择保存在该页，不覆盖项目默认值。“保留本页的图片与裁切”会添加作者图片锁；生成、换主题或同步来源都不会解除。
6. 要修订，打开同一节的“修订结果”，输入修订，如 `Use evidence-top; keep every word and other page`。Codex 也接受针对既有构图／精确数据图表补丁约定的普通说法。本地模式接受具名构图和有限的图表语法。对图表，若尚未绑定，请选择已有的精确数据集；缺少数据会停止操作。`Use dark-data` 会在本地应用一个有范围的类型化设计选择。其他修改请使用**更多 → 给开发者**里的编辑器，不要以为不支持的文字已被执行。“修订所选范围”运行前会显示范围说明，例如“范围：第 3 页。可能修改第 3 页的 composition、chart data binding、theme；其他页不变。事实、数字、单位和来源从不改写。”并列出该范围内的锁定。
7. 点**带走 → 放映**打开观众页面，带演示导航，没有编辑器控件。预览不等于已验收的导出。

界面语言与输出语言相互独立：**更多 → 语言**里有唯一的界面切换键和“输出语言”。输出语言决定起草语言与格式，不会悄悄翻译受保护的来源文字。提示词语言和语气不再是设置：草稿发送输出语言和中性语气。

## 三个方向（S9a）

原来的六个问题已删除。DeckWeft 把同一份内容画成三种样子；期望的材料多少由**样子**底部的**少／中／多**决定。三个预览的图形、字体、媒体和动效不同，事实完全相同。

1. 在**样子 → 三个方向**下选**少**、**中**或**多**：
   - 少：问题、证据、行动；
   - 中：再加背景与局限；
   - 多：全部六种论证单元。
2. 点**看三个方向**。改变档位会为当前文稿重新请求三个方向。预期舞台上出现卡片，每张卡片显示：
   - 已测量的预览，附带样例页按钮；
   - 该方向改变了什么：图形（底色、强调色、各样例页的版式、有多少页改变版式）、字体（展示、正文、数字字体与对比）、媒体、动效（会播放什么，或开启动效后会播放什么）和输出（PowerPoint 或 PDF 中 L1、L2、L3 元素各有多少）；
   - 一行适配说明，例如“✓ 在 1440 px 下 5 页全部适配”。

   卡片上方一行给出共同的事实哈希。高于 900 px 候选预算的页面会被列出，但不阻止选择。其他适配失败会使**使用这个方向**不可用。
3. 阅读卡片上方的“论证单元”。缺少的单元或没有依据的论点会变成问题，例如“第 3 页的论点由哪些数据、来源或引文支持？DeckWeft 不会替你编造。”不会为凑页数添加任何内容。
4. 点**使用这个方向**。该方向通过普通编辑路径应用到每一页；在此之前不会应用任何内容。**撤销**恢复之前的设计。用**别动这页**锁定的页面保留其主题与构图，卡片会说明保留了多少页。首次使用的**排好**会为刚做好的文稿显示同样的卡片。

如果没有出现方向，提示会说明原因：文稿为空、字段未知，或文稿有未保存的修改（请等状态方块显示已保存）。

### 图片审阅与页面规划（仅 API）

图片审阅和页面规划在单入口外壳里已离开浏览器。服务器仍会强制执行，API 可以运行它们：

- **页面规划。**`POST /api/visual/page-plan` 返回一张表：每页的论证单元和判定依据（*label*、*structure*、*keyword* 或 *position*）、文字长度与所需页数，以及材料不足之处的提问（例如“材料支持 5 页，目标为 9 页……DeckWeft 不会填充页数。”）。`POST /api/visual/page-plan/apply` 可以把缺乏支持的证据页标为“待补证据”（最终导出随后以 `EVIDENCE_REQUIRED` 拒绝），或把过长页面拆到重复标题的续页，不改写任何文字。目标超出 1–1000 会被拒绝（`PAGE_PLAN_TARGET`）。
- **生成之后（S9b）。**每份生成的文稿（本地或 Codex）在保存后，都按所选详细程度（未选则为“标准”）做规划。规划写明已起草的页数、材料支持的页数和目标，再列出问题。在 Codex 路径上，规划也随请求一起发送：提示词写明论证单元、每页容纳的字符数和目标，并禁止为凑数添加页面、事实或引文。提供了来源文字时，不含其中任何一行的起草页会被列出：“第 n 页不含你提供的任何一行；这是宿主添加的。”一次真实的 Codex CLI 运行检查过这条路径（[记录](../evidence/s9b-blueprint-a/codex-page-plan/page-plan.json)）。
- **工作台文稿的截图、审阅、报告和审阅后导出：**`POST /api/visual/workbench/:id/action`（`inspect` 即截图，以及 `review`）、`GET /api/visual/workbench/:id/report`、`POST /api/visual/workbench/:id/export`。更细的作者动作和 `POST /api/visual/migrate` 也只在 API 里。`tests/browser_workbench.mjs` 与 `tests/browser_author_controls.mjs` 会逐一调用它们，并保留原来浏览器步骤所做的断言。

浏览器里的后果：用**让助手帮我写**起草的文稿是工作台文稿，在图片审阅通过 API 完成之前，服务器会拒绝它的 HTML、PowerPoint 和 PDF 导出（`WORKBENCH_REVIEW_REQUIRED`）。用**排好**得到的不是工作台文稿，不受限制。浏览器里没有任何操作能批准导出。

## 存下一个样子以便复用

存下的样子保留主题、配置选择（色彩、对比、密度、动效、图像比重）、各类页面所用的构图，以及已绘制的字体与动效 token。它没有文字、数据、来源、图片或品牌字段。

1. 等状态方块显示已保存。打开**更多 → 备份与还原 → 存下这个样子**，在“配置名称”里输入名称。
2. 在本工作台中通过图片审阅的文稿，以该审阅作为接受依据直接升级。否则勾选**我接受这个样子**。
3. 点**存下这个样子**。预期出现消息，写明主题和构图选择数量。被拒绝时会写明原因：
   - `PROFILE_UNSAVED`：先保存。
   - `PROFILE_NOT_ACCEPTED`：通过审阅或确认接受。
4. 重新载入 Studio 并打开另一份文稿：该样子仍列在“存过的样子”里。选中它并点**用在这份文稿**。该样子会应用到当前文稿。
5. **下载**保存 JSON；**导入样子**把它加回来，若 id 已存在则作为副本。样子保存在 `<文稿库>/visual/profiles/`。若主题现在的绘制与存下时不同，应用时会列出变化的 token。按章节或页面范围应用只在 API 里。

## 实际截图（API 与发布门）

运行时没有外部依赖。截图是可选且明确的。要启用，请用 `/Applications` 之外的独立 Chromium 可执行文件启动 Studio：

```bash
node bin/deckweft.mjs studio --capture-browser /absolute/isolated/chromium
```

可执行文件不会从个人浏览器或配置中被发现、修补或重新签名。每次允许的操作都会启动临时配置，在本机回环地址提供派生产物，等待字体、图片与当前适配完成，再以 1440／390px 截取实际 PNG 字节。Node 内置 WebSocket 控制这个独立进程。PNG 哈希绑定现有质量回执。原生图片／图表／图解截图是对完整故事的补充，仍受现有 20 张图的宿主上限限制。交互式故事仍需要真实操作轨迹；缺少轨迹会阻止验收，而不是被伪造。密集滚动组件和穷尽的交互状态仍属于更大的关卡。

浏览器里没有截图或审阅按钮。请通过上面的 API 运行这些步骤（或 `node scripts/release-gate.mjs`，见[发布门手册](../visual-acceptance/README.md)）：

1. 用 `inspect` 截图，并为该次操作给出许可。没有配置该能力时，任务停在可恢复的预览，无法导出最终 HTML。
2. Codex 模式下，实际截图会附给所选宿主。每张必需图片都需要哈希一致的发现。现有质量检查、来源身份、范围、锁定和累计两轮修复预算仍然适用。
3. 本地模式下，作者检查每张原生图片，查看整个故事与组件，记录包括最弱一页在内的可见发现，选择通过／未通过，并明确声明已检查。仅加载文件不能证明你看过。机器适配从不自动给出作者判断。
4. 审阅后的导出只对当前通过的回执开放。来源、渲染器、截图变化，审阅未通过，或项目有更新的修订，都会阻止它。较早的实测预览导出路径即使客户端去掉元数据，也绕不过工作台审阅。

报告和 PowerPoint／PDF 导出报告会显示审阅声明（`author`、`host-metadata-only`、`host-pixel-control` 或 `unattested`）、结论和像素对照命中数／总数。“未运行”表示没有对照记录，与命中数为零不同。声明描述的是证据，不是判断是否正确。

对宿主起草的文稿，页面条上的缩略图会标出“宿主添加 · 未核实”及行数，**词**下方列出每一行添加的内容。批准前请对照你的来源核对这些论点。**带走**对话框显示证据行，`GET /api/visual/workbench/:id/report` 下载 `report.md`。任务的导出报告和 `report.md` 会列出总数和所在页面；较早只有计数的检查点会注明无法给出位置。页面移动时，这些标记仍附着在页面 ID 上。只有项目 JSON 不包含单独的任务证据。

## 继续与恢复

1. 重新打开已保存的视觉文稿（**更多 → 备份与还原 → 我的文稿**），在**更多 → 让助手帮我写 → 接着之前的做**里，于同一浏览器会话点“继续上次任务”。任务检查点和偏好与观众 HTML 分开，保存在本地视觉文稿库。
2. 另一个编辑器保存了较新内容时，操作会报告修订冲突，不会覆盖较新的项目。请显式点“同步已保存的来源”，然后重新截图并审阅。同步会保留作者锁、最近一次已接受的产物和累计修复预算。
3. 用“取消操作”停止宿主／截图工作。只有在所属服务器已停止后，才用“恢复被中断的任务”；正在运行的操作无法被抢占。重启后不会自动重试模型调用。
4. “存一份恢复文件”会下载完整的本地恢复记录，含原始来源和私密归档材料，请妥善保密。**更多 → 备份与还原 → 最近一次已接受的 HTML** 会在尝试失败后明确下载上一份已接受产物；当前候选不会被升级。**更多 → 之前的版本**可将某个已保存修订恢复为副本。

引用可以在观众 HTML 中保持公开。已归档的私密讲者备注、检查点、提示词和宿主回执不会渲染在其中。项目／检查点导出保留供恢复用的归档数据，因此不是观众文档。

## 添加材料、审阅故事、生成幻灯片（DWI-020 至 DWI-023）

1. 打开**更多**，进入**按提示来写**。在**可选的本地文本／Markdown 来源**中选择一个或多个 `.txt` 或 `.md` 文件（最多 12 个，每个不超过 256 KB，合计不超过 1 MB 和 12,000 个字符）。预期：选择操作前不会发生任何事。
2. 选择**先审阅故事**。预期：打开**审阅故事**，此时尚未生成任何页面。每页显示标题、各要点及其来自的文件和行号，并标注*来自你的文件*、*数字需要来源*或*文件说法不一*。
3. 查看红色列表：文件之间说法不一致的地方会列出两个数值及各自出处。系统不会取平均或替你选择；如有错误，请修改源文件。
4. 修改标题，取消勾选不需要的要点或页面，填写**给谁看？**和**看完后他们应该知道或决定什么？**，并从三个方向中选一个。
5. 选择**生成幻灯片**。预期：打开一份新文稿，原先打开的文稿在库中保持不变。含数字的页面会标为需要证据，因为本地文件不是网页来源。

未被读取的文件会在审阅顶部列出并说明处理办法：PDF、Word 和 PowerPoint 文件、图片（不会自动识别文字）、加密或非 UTF-8 的文件。看起来像是对助手下指令的文字只作为材料保留，绝不执行。文件中的链接作为文字保留，不会下载任何内容。

你自己运行的代理也可以不交文件而直接交接内容：向 `POST /api/visual/story/handoff` 发送 `deckweft-content-handoff` 第 1 版内容（[模式](../../schemas/agent-handoff.schema.json)）。它包含内容、来源和代理声明的能力；含有凭据样式字段或数值的交接会被拒绝，声明的能力不授予任何权限。其大纲同样经过审阅。

### 出错时

- *请先选择一个或多个文本或 Markdown 文件*：审阅至少需要一个可读文件。
- *文字合计超过 12,000 个字符*：请缩短文件或分成两份文稿；系统不会替你删减。
- `HANDOFF_UNKNOWN_FIELD`：交接中有本版本不支持的字段；请删除它。

## 页面旋钮与提示音（DWI-040 至 DWI-043）

1. 打开一份文稿。预期：**工作台**旁的旋钮显示 `1 / N`，两侧有 **‹** 和 **›**；单独的页码被隐藏，只保留一个位置显示。
2. 点击旋钮后按方向键、**Home** 或 **End**，或拖动旋钮。预期：每步一页；最后一页不会绕回第一页；松开时打开该页。**‹** 和 **›** 按钮无需拖动即可做到同样的事。
3. 在字段中输入时，方向键只移动光标，绝不翻页。鼠标滚轮不会翻页。
4. 勾选**提示音**，每翻一页会有一声短促轻微的咔哒。预期：勾选前不会发声；本机会记住你的选择；隐藏的标签页、演示时和自动化测试中都不发声。页码总会显示每一步，声音从不是唯一的反馈。
5. 没有打开文稿时，**带走**不可用，**排好**是唯一要做的事。

### 出错时

- 旋钮变灰：文稿只有一页。
- 勾选**提示音**后没有声音：先点击一次旋钮（浏览器只在点击或按键后允许发声），并确认标签页可见。
