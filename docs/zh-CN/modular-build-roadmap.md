建议采用“渐进 TypeScript 化、先改善演示体验、再形成自动生成闭环、最后扩展多 agent 和外部设计软件”的顺序。核心应是统一的数据与场景契约；SVG、Three.js、Figma、After Effects 分别承担适合的任务。

## 实施前基础与缺口

已核对 README、现行路线图、架构、验证记录和源代码，并在本机运行 Studio，检查五个界面状态。现有内容、布局、场景、导出、存储和宿主包装已分层，应保留。

| 需求 | 可直接复用 | 需要新建或调整 |

| 私密提词器 | 讲者备注、排练计时、估算语速 | 独立观众窗口、讲者侧栏、逐页跟随和自动滚动 |
| 夜间与无障碍 | 深色幻灯片主题、部分减弱动效逻辑 | 编辑器夜间模式、统一偏好、完整播放器动效策略 |

当前 bridge 只允许一个活跃 agent，`GPT-6 Astra` 只是偏好字符串，不能证明宿主真的使用了该模型，也没有 effort 控制。工作区演示只是给原页面增加样式类；导出的 HTML 则包含讲者备注。这两者都需要明确区分公开画面与私密资料。

本轮发现：`speechStats()` 以英文式字词组计数，连续中文句子可能只算一个词；`motion.duration` 被 schema 限制为 2–60 秒。提词时长不能直接复用这个字段。本工作区没有 Git 元数据，未来代码 agents 也不能假设已经具备 worktree 隔离。

## 1. TypeScript 值得采用，但从边界和新增模块开始

优势主要在后续复杂度：不同素材和场景节点、任务状态、宿主能力、进度事件可以通过类型区分。它有助于提前发现“任务已完成却没有产物”“导出器收到未知节点”“讲者消息结构错误”等问题。渲染速度、图片质量和布局效果仍取决于实现。

分三步调整：

1. 给稳定 `.mjs` 边界补 JSDoc，限定范围启用 `allowJs`、`checkJs`。从现有 schema 生成或核对项目声明；持久化契约仍由 `schemas/project.schema.json` 决定。JSON、HTTP、MCP、provider 与宿主事件先接收为 `unknown`，经过运行时验证再使用。参见 [TypeScript 渐进迁移支持](https://www.typescriptlang.org/tsconfig/allowJs.html)。
2. 新增 Node 模块用 `.mts`，输出 `.mjs`；浏览器用 `.ts` 输出 `.js`。Node/DOM 分开配置，启用 `strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`，使用显式类型导入和 ESM 路径。开发工具固定版本，产物进入 `dist/runtime`，CLI、静态资源白名单和插件打包统一读取构建清单。
3. 随功能改动逐步迁移旧模块，检查编译后的运行时、离库插件包与调试映射。AE 的 JSX 保持宿主兼容，不能假定其支持现代 TypeScript/Node ESM。无需同时引入 React 或其他 UI 框架。

迁移期间保留当前 JavaScript 启动入口。全量切换会增加开发期编译步骤；最终用户需要预编译 JavaScript 的发行包，未编译的源码 ZIP 无法默默维持当前“无需安装依赖即可启动”的承诺。迁移 launcher 前必须解决这项包装取舍。[Node 原生类型剥离](https://nodejs.org/api/typescript.html) 不做类型检查，也不读取 `tsconfig.json`；项目最低版本仍是 Node 22.0，不能拿本机较新 Node 的行为代表全部支持范围。

建议的新目录职责如下，目录名表示规划，不代表已经创建：

| 模块边界 | 未来职责 | 复用当前代码 |
| --- | --- | --- |
| `src/contracts/` | Project、Asset、Scene、Job、Event、Host 类型 | schema、`src/core/validate.mjs` |
| `src/planning/` | 叙事、视觉意图、模板选择 | `src/core/model.mjs`、`src/layout/engine.mjs` |
| `src/assets/` | 本地素材、哈希、来源、许可 | `src/render/assets.mjs`、`src/layout/showcase.mjs` |
| `src/presentation/` | 观众数据投影、同步、语速和提词 | `src/core/speech.mjs`、`src/render/player.mjs` |
| `src/orchestration/` | 授权、任务、事件、调度、effort 策略、串行集成 | `src/services/agent-bridge.mjs` |
| `src/adapters/hosts/`、`src/adapters/media/` | 宿主能力协商和可选素材 provider | MCP adapter、worker CLI |
| `ui/workspace/`、`ui/presenter/`、`ui/audience/`、`ui/settings/`、`ui/jobs/` | 分开的浏览器界面与状态 | `public/app.js`、`studio-tools.js`、`agent-bridge.js` |
| `src/render/`、`integrations/` | 统一场景的导出和外部软件交接 | 现有 SVG/HTML/PPTX/Figma/AE 实现 |

本提案没有新增依赖。真正加入 TypeScript 工具前，试点记录捕获的契约错误、冷/增量编译耗时、精确包体、许可证和离线构建条件。TypeScript 为 Apache-2.0；Node 类型声明及其他开发工具另记许可和体积。编译器不进入用户运行包。新增渲染库也要说明实测收益、打包成本和离线行为，优先复用已有 Three.js。

## 2. 先生成“这一页应该如何解释”，再选择技术

建议的流水线是：用户主题和目标 → 叙事提案 → 每页视觉意图 → 模板/素材请求 → 统一派生场景 → 排版和可访问性检查 → 预览和导出。修改一页时只重建受影响的计划与素材，用输入哈希判断缓存失效。

每页 `SlideIntent` 包含论点、观众、依据、视觉家族、素材需求、交互目的和讲者脚本。先做对比、流程、时间线、指标、图文和克制的封面。真实数据图依赖明确数据；装饰插图不能被当成研究或事实证据。

新增版本化素材注册表：本地内容哈希、MIME、尺寸、来源、生成记录（不含密钥）、许可/使用范围、替代文本、裁切焦点和降级表示。二进制存在本地素材目录，避免塞进项目 JSON 或突破现有 JSON 请求上限。导入核对路径、大小与文件类型。项目 schema 与运行时校验同步演进，新版通过显式迁移保留原件；不能借自由 `extensions` 绕过公开能力的契约验证。

| 视觉任务 | 首选实现 | 导出规则 |
| --- | --- | --- |
| 流程、关系、对比、数据 | 原生场景文字/形状，受限 SVG | 保留文本与数据；拒绝脚本、外来执行内容和远程资源引用 |
| 照片、插画、纹理 | 经授权的图片工具/provider 或本地素材 | 单独图片对象，保留来源、许可和替代文本 |
| 入场、揭示、强调 | 场景节点 ID 上的声明式 MotionPlan | HTML 播放；PPTX 明示静态降级；AE 显式映射 |
| 标签切换、逐步解释、参数探索 | 白名单交互状态机 | HTML 支持键盘/触控与文本替代；静态输出保留选定状态和说明 |
| 有意义的空间或 3D 解释 | 可选 Three.js adapter | 懒加载、资源限额、静态降级、统一动效偏好 |
| 统一主题模板 | theme tokens + 语义布局配方 | 主题保持一致，内容决定结构，避免只换背景色 |
| 设计精修与专业动态成片 | Figma / AE adapter | 作为可选下游分支，分别做实机验收 |

Astra 可以规划、写代码和调用工具；其原生图片模态是输入，图片生成通过另外的工具完成。选择 Astra 不等于取得图片工具、Figma 或 AE 的账号与执行权限。[Astra 官方能力说明](https://developers.openai.com/api/docs/models/gpt-6-astra)。

对每个节点和行为记录 `native`、`static-fallback`、`unsupported`。导出前预览降级结果；不允许把整页栅格化来掩盖缺字、布局或交互缺失。新节点需增加包结构/可编辑性检查和真实目标软件的视觉验收。通用 3D 场景不代表能在 PPTX/Figma/AE 中成为原生可编辑 3D。

## 3. Dots 接管：先单宿主闭环，再多对话并行

这里把任务分成 `deck-generation` 和 `code-change`：前者返回项目/素材提案，后者返回限定范围的补丁、产物清单和测试证据。允许生成幻灯片不自动允许修改仓库代码；允许某个对话参与也不自动开放其他对话。

需要三个核心契约：

| 契约 | 必需内容 |
| --- | --- |
| `DelegationGrant` | 精确对话 ID、读取/发消息等操作范围、选定记录快照或后续消息范围、项目/代码路径、宿主/agent、模型和 effort 上限、网络/工具、预算、并发、有效期与撤销 |
| 执行胶囊 | 已采纳任务 ID、`roadmap.json` 版本/哈希、相关 AGENTS 规则、源码/schema 哈希、基线 revision、输入、验收命令、grant ID |
| `HostAdapter` | 能否读取/操作指定对话、可用模型/effort、能否切换模型、并发、取消、用量和事件能力 |

创建对话、读取其他对话、发送消息或继承文件都要在用户授权范围内，并由实际宿主支持。本轮只规划，不执行这些操作。撤销授权停止新任务并拒绝迟到结果，已生成的本地草稿保留供审阅。

Dot 每次领取的是锁定版本的执行胶囊；路线图变化产生待确认的重新规划，不能偷偷扩大运行任务的权限、预算或验收范围。只读取正式采纳的任务；这份 proposal 本身不是可自动执行的路线图。导入的文稿依旧是数据，不能变成执行指令。

记录请求模型、宿主自报模型与 API 返回确认的模型，effort 同样区分。缺少切换能力时显示“等待宿主设置”，不能把请求 Astra 当成已执行，也不能默默换模型。现有 bridge 只存一个 agent，第二个 session 会被拒绝，需先通过真实单宿主握手再改多 worker。宿主模式与未来可选 API 模式分别授权，不推断订阅、账单或自动复用凭据。

生命周期建议为 `queued → running → validating → needs-review → applied`，另有 blocked、failed、cancelled、expired。产物生成完成与用户采用是两个状态。持久化有限的事件，包含 job/task/attempt/worker ID、单调序号、时间、输入/输出哈希和简短状态。密钥、租约令牌、完整私密对话不进入项目、进度事件或导出文件。同步采用可续接的事件流或带游标的轮询，本地记录不会上传成为遥测。

并行时先统一叙事和设计约束，再分派独立页面、素材或文件；只有一个集成者写入最终结果，并检查基线哈希/revision。代码 worker 在真实 Git 仓库可使用独立 worktree；当前工作区应使用隔离副本与哈希固定的补丁。基线变了就报冲突。检查点验证后才可续跑；重试带幂等键，取消无用子任务。付费图片请求若结果不明且 provider 不支持恢复，不应盲目重复计费。

首版并发建议为 2，观察争用、输出一致性和实际收益后再增大。规划、依赖等待和集成仍是串行环节。普通本地生成无需自动新建对话或给其他对话发消息。

**进度条与时间线**应显示 agent、当前任务、已验证产物、状态、耗时和下个依赖。总进度按锁定 DAG 的预计工作量加权，任务验证后计入；任务内部只有真实计数才显示百分比，例如 6 张素材已完成 3 张。不透明模型推理显示不定进度，不拿 token 数或运行秒数冒充完成度。

ETA 基于同类任务历史、模型/effort/工具组合、排队、并发和关键路径，显示区间、置信度/样本量。没有足够历史就显示“正在估算，缺少可比较记录”。等待授权、额度、工具和用户审阅单列；宿主断连不能继续给出确定结束时间。范围变化显示新版本估算；无障碍播报只报关键里程碑，避免不断读进度。

**Astra 的性价比策略**：以 `medium` 作为有边界的叙事/视觉规划初始候选，复杂综合、布局修复和集成试 `high`；简单抽取可测 `low`；schema、排版适配和包结构检查用确定性代码。`xhigh/max` 只在收益可测时使用。官方也建议根据代表任务评估较高 effort 的质量与延迟取舍，没有通用的最优档位。[OpenAI 部署检查表](https://developers.openai.com/api/docs/guides/deployment-checklist)。

试验覆盖英文 pitch、中文/混排、证据密集、图片、交互与代码修改；固定输入，先比较 medium/high，适当重复并盲审。记录首轮 schema/排版成功率、事实支持、图文相关性、可编辑性、返工次数、人工接受时间、延迟和实际返回用量。先复用批准的素材隔离图片随机性，再测完整链路。

选择达到质量门槛后的最低总成本策略，包含返工和集成。API 模式有真实用量时，采用带日期的价格计算文本、图片、工具和重试；宿主没有价格/用量信号时就标明未知，用延迟和返工比较，不能把订阅额度等同美元。记录评估日期、语料/策略哈希和宿主模型版本，重大变化后复测。失败升级必须在预先允许的 effort/预算上限内。

## 4. 按钮：颜色区分角色，形状遵守有限规则

保留现有图标栏和焦点工具，建立统一 action registry，集中管理文字、图标、快捷键、颜色角色、形状和可用状态。初始方向：生成紫色，主要文档操作蓝色，演示青绿色，危险操作红色，导航中性。具体色值在亮暗模式中核对前景/背景对比后确定。

主要动作使用带文字的圆角矩形；局部工具使用方形图标按钮；持久状态使用胶囊开关；互斥模式使用分段控件。避免每个按钮各造一种形状。危险按钮与导航分开，保留撤销/恢复。悬停与键盘焦点均可看到名称，陌生的重要动作不只靠 tooltip。

空间主要从分组、减少同时突出的动作、收起四布局比较区和把低频操作放入有名称的更多菜单获得，不靠缩小点击区域。固定视口实测画布面积和完成任务的步骤，当前不预设节省百分比。

颜色不能是唯一线索，参见 [W3C 颜色使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)。至少按 WCAG 的 24×24 CSS 像素及其间距/例外规则核对目标，触控优先以 44×44 为产品目标；图标可以小，热区不能混为一谈。参见 [W3C 点击目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。验收包括键盘、200% 缩放、窄窗和真实屏幕阅读器。

## 5. 提词器：观众看画面，讲者持续看到解释内容

独立观众文档只包含公开的场景投影。它不应收到讲稿、隐藏备注、完整项目 JSON、授权数据、模型日志或私密来源说明。同一编辑器会话的新标签页加隐藏侧栏并不是隐私边界。采用独立且受限的 loopback origin，不提供编辑器 session 或通用项目端点，避免观众页从现有同源 session 接口取得编辑器凭据。使用演示会话范围的只读观众能力；消息只传页面 ID、场景版本、播放状态和允许公开的视觉/交互数据，检查 origin/session/消息结构，适当隔离 opener。讲者服务只发布已经过滤的公开投影。

讲者页同时保留当前页、可伸缩/停靠的 pitch 侧栏、下一页、计时、语速、暂停继续和翻页。换页时直接切换对应脚本，不再逐页进入二级菜单。侧栏宽度、字号和读到的位置按本地演示保存；编辑备注时不抢快捷键。

英文按 words/min，中文按 characters/min 独立校准，混排分别计数且不重复，加显式停顿和提示时间。讲稿时长、自动翻页时长、入场动画时长分别建模，不把超过 60 秒的解释压进原动效字段。先用会话 timing sidecar；需要保存为 deck 内容时再采用版本化类型契约。

讲者点击开始后自动滚动。手动滚动暂停跟随，提供“继续跟随”；暂停保留当前位置。调整语速、侧栏宽度后重算换行并保持文本锚点。减弱动效时改成手动分页或离散高亮，不能重新启动平滑滚动。自动翻幻灯片另设 opt-in，不因提词滚动而强制翻页。首版用人工计时校准即可，麦克风或语音跟随放在后续可选能力。

投屏只选择观众窗口/标签页，或使用扩展第二屏。镜像屏幕或共享整个桌面会暴露讲者内容，网页无法保证隐藏。验收必须真实共享一次，并覆盖弹窗阻止、刷新、断连、关闭和黑屏恢复；观众窗口打不开时提供重试入口，不能把私密讲稿临时搬到观众画面。

导出也分观众版和明确请求的讲者版。当前 HTML 直接包含备注，CSS 隐藏无法阻止共享文件泄露。观众版彻底省略私密备注 DOM/JSON/元数据。PPTX 同样显式决定是否包含 speaker notes：观众版默认不含，讲者版保留。分享和外部软件交接要显示这种区别。

## 6. 夜间模式和无障碍：集中设置，区分三个层次

分别管理编辑器外观、deck 主题、观看者播放偏好。编辑器外观用 `system | light | dark`，跟随系统时实时响应 `prefers-color-scheme`，手动选择后保持覆盖。以后可增加用户指定的本地定时，不需要为了日落换肤获取位置。对话框、输入框、任务面板和讲者控件都换肤，幻灯片内容保持原主题；观众页由 deck 主题决定。

设置中保留一个快捷“减弱动态效果”开关，高级项为 `system | full | reduced | off`。实际播放尊重用户明确减弱需求与操作系统偏好，作者不能强制重新打开动效。环境偏好本地保存，不写入项目；作者的动效设计仍属于 deck。若要全 deck 去动画，另提供有明确含义、可撤销的内容操作。

同一策略作用于 CSS、Web Animations、Three.js、粒子/背景、视差、重播、提词滚动与导出播放器。关闭时取消已启动动画和渲染循环，进入有意义的静态状态，重播也不能偷偷开启。reduced 去除连续/空间运动，off 去除全部非必要 deck 动画，交互和焦点仍可用。提词器始终有独立暂停/手动控制。参见 [W3C 暂停、停止、隐藏](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)。

设置页用紧凑的外观/可访问性分组，常用入口清楚，高级选项折叠。高对比度、字号、键盘和读屏本身要做好；一个“无障碍模式”开关不能代替这些能力或证明合规。避免重复的逐页观看偏好。
