# 墨尔本 3 分钟展示指南

展示幻灯片和讲稿使用澳洲英文。这份中文指南帮助你排练、理解技术和处理现场状况。

## 先打开什么

1. 打开 `deckweft-melbourne-pitch.html`。应看到 8 页主讲，后接 3 页问答。
2. 左右方向键翻页。排练时点 **Start 3 min**。计时器不会自动翻页。
3. **Speaker notes** 会在同一个窗口显示讲稿。镜像投屏时观众也会看到，只在私人屏幕或排练时打开。
4. 需要修改文字时打开 `deckweft-melbourne-pitch.pptx`。文字和技术架构图可编辑，Studio 截图保持图片。不要把截图当成可编辑界面。
5. 其他参赛者可用 `melbourne-demo-template.pptx`。替换所有方括号内容和截图区域，删掉没有证据的数字占位项。

模板是可编辑 PPTX，不是 `.potx` 母版，也没有给 Studio 新增主题。`pitch.deck.json` 和 `template.deck.json` 可导入 Studio，但只使用现有预设主题和四类布局，外观会与特别设计的 PPTX 不同。`stage-demo.deck.json` 是专供现场操作的简短三页示例。

浏览器如果阻止本地 HTML，可以使用 PPTX。也可在仓库根目录运行 `python3 -m http.server 4188 --bind 127.0.0.1 --directory dist/melbourne-demo-kit-final/output`，打开终端打印的本机地址。结束时按 Ctrl+C。播放器没有远程字体、上传或统计请求。

## 3 分钟节奏

| 时间 | 内容 | 要完成的事 |
| --- | --- | --- |
| 0:00–0:15 | 第 1 页 | 让人理解“项目做好了，还需要讲清楚”。 |
| 0:15–0:35 | 第 2 页 | 描述新人准备展示的难点，注明这是产品假设。 |
| 0:35–0:55 | 第 3 页 | 讲清现有 alpha 的流程与安装要求。 |
| 0:55–1:45 | 第 4 页 + Studio | 改一个标题、换一次布局、保存。 |
| 1:45–2:10 | 第 5 页 | 用纸条、排版桌、打包盒解释技术。 |
| 2:10–2:30 | 第 6 页 | 说有证据的实现事实。 |
| 2:30–2:45 | 第 7 页 | 介绍尚未开展的五人测试计划。 |
| 2:45–3:00 | 第 8 页 | 邀请对方带一份提纲来试用，结束。 |

主讲到第 8 页就停。问答时再按需打开后面三页。遇到临时缩短为 90 秒，使用 1、3、4、5、8 页，演示只做一次布局切换。

## 现场演示的准备

1. 在仓库根目录运行 `node bin/deckweft.mjs studio --port 4187 --home dist/melbourne-demo-kit/studio-library`。需要 Node.js 22+。打开 `http://127.0.0.1:4187`。这是单独的本地项目库，不影响已有资料。
2. 点 **Import JSON / outline**，粘贴 `stage-demo.deck.json` 内容并导入。预期出现三页，第一页标题为 “Our build is ready”。若提示 ID 已存在，通过 UI 导入为新副本，避免覆盖。
3. 演示前选中第一页，让标题输入框和四个布局缩略图可见。按投影仪分辨率排练。关闭私人窗口和通知。
4. 到 0:55 切到 Studio，把标题改成 “Our build is ready to share”，点另一种布局，再点 **Save**。预期文字保留、布局变化、保存完成。
5. 只有排练证实来得及，才现场导出 PowerPoint。否则展示已准备的 `stage-demo-core-export.pptx`。它确实由 DeckWeft CLI 导出，但文字拟合使用离线估算。
6. 1:45 前返回第 5 页。任何步骤卡住超过 5 秒，就返回第 4 页截图，说明它是实际界面截图，然后继续讲。不要在台上排错，也不要称截图为现场成功结果。

漂亮的主讲 PPTX 是单独编排的展示示例。它不是现有四布局引擎自动生成同款视觉的证据。材料同时提供真实的核心导出文件，方便对照。

## 像给五岁孩子解释

你把每个想法写在一张纸条上，这就是内容。DeckWeft 像一张整洁的桌子，会试四种摆法，检查文字是否放得下。导出器像打包盒，把选好的摆法带走。打开 PowerPoint 后，字还是可以修改的字。

JSON 就是电脑看得懂的带标签清单。Schema 是检查清单，规定哪些标签和值合法。Scene 是摆放地图，记录每段文字、每个形状的位置。“本地”表示 Studio 的项目存在你的电脑，服务只监听本机；仍然需要 Node.js 和浏览器。

Codex 可以通过安装好的宿主技能帮你起草提纲。账号、联网和数据处理由宿主另外决定。DeckWeft Studio 本身不内置模型，排版使用明确规则。布局分数衡量规则匹配与文字适配，不衡量事实真假、商业价值或是否应该获奖。

## 高频问答的答法

**为什么要做这个，已有工具不够吗？** 我们探索一个很小的工作流：短提纲、四种可解释布局、本地可编辑导出。人们是否更喜欢它，需要实际试用验证。不要无证据贬低其他产品。

**AI 在哪里？** 宿主 agent 可写提纲；本地引擎负责检查、排版和导出。仓库已有经检查的 Codex CLI 技能运行记录，但完整宿主验收、桌面原生激活仍未完成。

**能离线吗？** 已准备的 HTML 和核心 Studio 编辑、导出不需要网络。可选的 AI 起草可能需要宿主账号和联网。

**文字太多怎么办？** 会报告阻塞。选定 scene 放不下全部内容时，视觉导出停止。可以删减、拆页或换布局。浏览器使用 Canvas 实测，CLI 使用离线估算。

**当天做了什么？** 只说真实发生的贡献。DeckWeft 在活动前已存在，这套模板和 pitch 为活动准备。把当天实际修改补充到英文指南的记录里，不要说整个项目今天从零完成。

**下一步如何验证价值？** 计划找五位自愿新人，各带一份粗提纲，观察完成任务的情况、卡点和能否讲清楚。该测试尚未开展，不能声称已节省时间或已有客户。

## 为冷水壶努力的重点

这里是排练建议，不是官方评分表。前 15 秒让人听懂用途；现场让大家看到一次明确变化；用一句话解释结果；给出具体下一步；3 分钟准时结束。找一位愿意帮忙的人听完后复述用途，优先修改他们误解的部分。未经许可不要录音、引用或保存联系方式。

冷水壶是动力，主讲仍聚焦产品。如果 demo 后现场气氛轻松，可以自然地说：“I came to build something useful, and I would be pretty chuffed to take that Dot bottle home.” 意思是：我是来做有用的东西的，如果还能把那个 Dot 水壶带回家，我会很开心。不要把得奖承诺写进产品能力。
