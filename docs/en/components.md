## Data rules

Supported `chartType` values are `line`, `area`, `ranked-bar`, `stacked`, `scatter`, `heatmap` and, since S4, `grouped-bar`, `dot-interval`, `small-multiples` and `benchmark-table` ([chart kinds](#chart-kinds-and-declarations-s4-2026-10-19)). An older v3 chart without `chartType` remains a zero-inclusive line chart. Existing v1/v2 inputs stay on their existing paths; migration remains explicit.

Every series has one finite number or `null` per category. No string-to-number conversion, interpolation, missing-to-zero conversion, automatic percent normalization, or source-order mutation occurs. Zero is a real observation. Null line/area entries break the path. A stacked category with any missing member has no stack; its exact partial data remains in the table. Positive and negative stacks accumulate separately. Ranked bars sort a derived view of one series by `sort` (`value-desc` by default, `value-asc`, or `author` for a direct-labelled bar in source order), with stable ties and missing entries last. Stacks may declare a value sort by their net total. The accessible table keeps original source order.

Scatter series require numeric/null `xValues` and a dataset `xUnit`; a point needs both coordinates. All tables and mark labels retain the original numeric value. Tick labels can be rounded for space and are not replacement data. Very long labels can fail measurement; use another composition or explicitly edit the label, retaining a source citation.

`axis.policy` is `zero` (default), `extent`, or `fixed`. Fixed axes require increasing `min`/`max` and cannot exclude values or signed stacked totals. Area, ranked bars, grouped bars and stacks require zero inside the range unless the chart declares `truncation: {note}`; a declared truncation draws a break mark at the axis start, labels the caption **truncated axis** and shows the note under the chart ([field list](architecture.md#version-3-handoff-fields-s1-2026-10-19)). Empty data uses a visible 0–1 axis; constant data receives derived padding. Neither changes stored observations. Heatmap color intensity uses the displayed domain; sign colors, literal values and a separate missing-cell outline do not require color interpretation. Series names label matrix rows; its legend describes sign/missing semantics.

For time categories, set `categoryKind: "datetime"`, an IANA `timeZone`, and strictly increasing ISO instants with an explicit `Z` or numeric offset. Original instants remain in the table. Display labels use the declared zone, and line/area spacing uses elapsed time. Invalid calendar dates, ambiguous local timestamps and invalid zones fail validation. The example crosses Melbourne's October daylight-saving transition. Category data has no inferred time zone.

## Chart kinds and declarations (S4, 2026-10-19)

Every chart is one figure drawn from one data object: the question and caption, the plot, the legend, visible notes, the takeaway, the data definition and **View all data**. The same object produces the static view, the interactive view (the runtime embeds the same `chart()`), the text statement and the table, so no number is typed twice. A theme changes type, stroke, colour and label placement; it never changes data, units, sources, `betterDirection` or the table, which is byte-identical in all three themes. State: **LocalVerified** in English and Simplified Chinese at 1440, 1024 and 390 px ([evidence](../evidence/s4-chart-renderer/review.md)).

| Kind or field | Expected result | Recovery when rejected |
| --- | --- | --- |
| `ranked-bar` (C01 with `sort: "author"`) | One row per category: the label, the bar, and the exact value at the bar end. On screens up to 700 px the label sits above its bar; nothing scrolls. `value-desc` (default) and `value-asc` rank; `author` keeps source order. | Ranked bars take exactly one series; use `grouped-bar` for two or more. |
| `grouped-bar` (C02) | One group per category in author order; every bar line repeats its series name, so the series stay apart in black and white. | Needs two or more series and a zero baseline (or `truncation`); a log axis is rejected. |
| `dot-interval` (C09) | A dot per value with its interval line and end caps, and the value with bounds as text (`40 [34–47]`). Up to 700 px the text sits above its interval. A note states the interval type, level and method. | Every series needs an `interval`; one type and level per dataset (S1 guard 4). |
| `line` with `labels: "end"` (C13) | No per-point labels; each series ends in a direct label with its last value (and the category when the last value is missing earlier). Labels never overlap. | `labels` applies to `line` only. |
| `small-multiples` (C17) | One panel per series on one shared scale, stated under the chart; other series stay as faint context. Each panel names its series and last value in text. | Needs two or more series. |
| `benchmark-table` (C05) | A table with units in each column header, missing reasons in cells, numbered qualifier marks and notes, and a boxed **best** mark per column under `betterDirection` (qualified values are never marked best). Up to 700 px each row becomes a labelled card. | Qualifiers need `categoryIds`, one per value, and never sit on a null. |
| `focus {categoryIds}` / `focus {seriesIds}` | Focused bars or rows are solid; the others are lighter and outlined; focused series are thick and the rest muted. The legend names **Focus** and **Other categories** (or marks the focused series). | A single-series chart can only focus categories. Name existing ids; a series focus may not name every series. |
| `axis.scale: "log"` | Whole-decade ticks and the note "Log scale: equal steps are equal ratios" on line, scatter, dot-interval and small-multiple charts. | Other kinds answer `CHART_SCALE_UNIMPLEMENTED`; filled kinds are rejected (S1 guard 2). |
| dataset `events` | Numbered dashed rules on line, area and stacked axes, numbered marks beside bar and table rows, and a note per event with its relation (`adjacent in time; not a cause` or `attributed in a cited source`). | Scatter and heatmap answer `CHART_EVENTS_UNIMPLEMENTED`. |
| series `interval` | Whiskers on line points, intervals on dot-interval charts, bounds in the table. | Other kinds answer `CHART_INTERVAL_UNIMPLEMENTED`; uncertainty is never dropped silently. |
| dataset `missing` | The value stays a gap; the label and table cell read **Missing · not collected** (or the declared reason) and the note gives the explanation. | — |
| chart `question` / `takeaway`; dataset `definition`, `version`, `collectedAt`, `validPeriod` | The question heads the figure; the takeaway follows the legend; denominator, sample, normalization, better direction, version and dates appear as one visible line. | — |

Labels a chart needs for its conclusion (category and value labels, end labels, panel titles, table cells) carry `data-conclusion-label`. The browser fit check fails, and Studio refuses export with `VISUAL_FIT`, when one of them is hidden, clipped, only reachable by scrolling, outside the viewport or covered by another. If export is refused, shorten the label, choose a wider composition or another kind; never hide the value. Point labels on line, area, stacked, scatter and heatmap charts are not conclusion labels yet: on narrow screens those plots still scroll inside the figure.

## Stable relationships and original code

Diagram types are `relationship`, `sequence` and `process`. Edges draw exactly their supplied `from`/`to` direction; no adjacency or extra relationship is inferred. Sequence messages follow the supplied edge order. Optional edge `id` values and node `id` values share a unique namespace. Automatic routing is bounded, not an optimal graph-layout engine; inspect complex graphs and use the exact relationship list as the static text representation.

Annotations use `target.blockId` and optionally a diagram `objectId`, chart `objectId` (a stable `categoryIds` entry) with optional `seriesId`, or code `line`. Chart category identities have exactly one entry per category. An annotation and its target must share a scene. Scene movement, ranked sorting and composition selection retain these identities. Deleting a target fails rather than retargeting by array position. Code line references are authored line numbers; when inserting code lines, explicitly update the reference and emphasis as part of that edit.

Code is escaped text, never executable input. Tabs, CRLF/LF, trailing spaces, final newlines and the source anchor survive HTML/JSON. Emphasis wraps original lines without inserting text. The raw editor preserves uniform LF or CRLF; mixed line separators use the escaped JSON editor to avoid textarea normalization. Source URLs remain manually followed links; the app does not fetch them.

If a JSON edit fails, repair the field using the displayed message. Export **Project JSON** before leaving to retain unapplied drafts. Locked blocks and shared datasets stay protected by save-time checks. For a stale revision, retain your backup and reopen the current document; use History to restore an earlier revision as a separate copy. No runtime dependency, remote service or automatic image request is added. VIS-009 interactions remain future work.
