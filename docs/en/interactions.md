# Semantic interaction and replay

[简体中文](../zh-CN/interactions.md) · [Components](components.md) · [Evidence](../evidence/vis-009/review.md)

## Apply to an existing work

1. Open your saved work in Visual Studio. Choose a page, switch on **Look → Let this page move**, then press **Add explanations to this page**. This adds selection controls to existing charts and steps to existing diagrams; it creates no new deck or page. Existing interactions stay intact. Locked content must be unlocked explicitly first.
2. Charts without category identities receive new stable identities once, as part of this explicit action. Values, order and units stay intact. Use the category range and the **Show:** checkboxes to change which data the chart draws, and the **Focus:** buttons to emphasise one series (see [Focus one series or hide it](#focus-one-series-or-hide-it)). The legend, selected-data table, status line and explanation line use the same selection. The full original dataset remains available.
3. Edit the step labels and explanation fields. New diagram steps reference supplied edge identities when every edge has one; otherwise they reference existing nodes. Initial text uses only supplied labels/notes. Selecting an edge highlights it and its endpoints together with the explanation. Author fuller explanations in these fields as needed.
4. Set **Page transition motion** to **Subtle**, **Off** or **Follow theme**. Global Motion Off and system/user Reduce motion take precedence. Finite transitions follow the selected chart/step; replay and Next cue use the same state reducer.
5. Explore the chart or step in the preview, then choose **Use current chart / step as opening** to retain that choice, including a focused series. Wait for the state square to show saved and for the page to be measured, then choose **Take away → HTML**. Reopen and offline HTML start from that authored selection. Temporary audience exploration stays transient. The opening action does not change image comparisons/hotspots or the authored cue order. Expected refusal: when the preview stands at a later cue position that you did not explore (for example the static state it opens on), Studio answers **The preview shows cue position 1 (the static state), not an explored selection** and changes nothing. Recovery: change the chart or step in the preview first, or move **Cue position** to 0, then choose the action again.
6. If the preview rejects a plan or export is disabled, repair unapplied JSON/fit errors first. Undo restores the previous author state; Project JSON retains a backup. Workbench projects continue to require their existing image review before export. Native v3 PowerPoint/Figma/AE compilers remain unavailable.

The optional interaction examples below exercise the same editor and runtime.

1. Run `npm run studio:interactions` with Node 22 or newer. Open the printed loopback Visual Studio address. Choose an English or Chinese story under **More → Backup and restore → My decks**. Another library can use **More → For developers → More examples → Interactive examples**. Each 15-page story retains the existing four-page material and exact component examples.
2. Select a chart page. Use **From category**, **To category**, the **Show:** checkboxes and the **Focus:** buttons. Marks, labels, legend and selected-data table change together. **Full original dataset (unfiltered)** keeps the original order, values, nulls, units and time instants. Unchecking the last series or reversing the category range is refused; the previous valid selection remains.
3. Select the image comparison page. Choose **First image**, **Second image** or **Compare both**. The actual image view changes, including its authored crop and alternative text. Arrow Left/Right and Home/End select tabs. The example compares two authored crops of one local illustration; it makes no historical before/after claim.
4. On the image narrative page, activate a numbered hotspot. Its source-bound annotation and original-image coordinates appear. Activate it again to collapse the explanation. All original annotation text remains on the page.
5. On diagram/code pages, choose an explanation step. A diagram shows the supplied node or directed relationship and authored explanation. Code shows the original referenced lines in a separate excerpt, with their line numbers; the complete original code, whitespace, emphasis and source anchor stay intact above it. Arrow keys and Home/End also move between step buttons.
6. Choose **Replay cue sequence** to reset and play the authored cue order from the opening, one cue per second. **Pause cues** stops at the current boundary and the same button then reads **Play cues**, which continues from there (from the end, or after exploring, it starts again at the opening). **Previous cue**, **Next cue** and the cue-position slider select a deterministic prefix from the authored initial state. Native keyboard Home/End and arrows operate the slider. Manual exploration is temporary; replay/seek recomputes the authored sequence independently of it.
7. The operating system's reduced-motion setting removes visual animation while leaving all controls, explanations and cue playback functional (a scene with `reducedMotion: "static"` shows its static state instead; see below). The exported page has no motion toggle of its own and follows that setting, also when it changes while the page is open. The author's global motion **Off** also wins over an individual scene's subtle motion. Switching scenes or browser tabs stops that scene's cue timer, finite animations and registered resources; it retains the current information state. Replay, Play cues or Next cue can continue after returning.

Mouse, keyboard and touch use the same semantic actions. Controls have native focus behavior and at least 44px touch targets. No-JavaScript reading shows complete original graphics/data/code, both source images and expandable authored explanations/cue order. A scene with a declared static state shows that state instead: the frozen chart selection, step, comparison tab or hotspot, with a text statement of what it shows; nothing is removed from the page. Reading mode permits local horizontal scrolling for large charts, diagrams or exact code. Print requests show static content without playback controls. Actual screen-reader, real IME and broader print/application acceptance remain separate gates.

## Freeze a static state

A static state is the key state that exported files without JavaScript show, that the player opens on, and that reduced motion falls back to. [Evidence](../evidence/s2-vertical-sample/review.md) · [Known conflicts](../plans/design-handoff-vertical-sample.md#conflict-list).

1. Key states come from the project JSON (`keyStates` on a scene: an `id`, a cue `position` and an optional `label`; 0 is the authored opening). Studio cannot create them yet. To use them, import the project with **More → Backup and restore → Import a deck**.
2. Open the page and switch on **Look → Let this page move**. Next to **Use current chart / step as opening**, set **Still picture for print** to a key state, for example `1 · Structure-first habits (3 of 6)`. Expected: the preview shows that selection, the cue position reads `1 / 2`, and a line above the chart starts with **Static view** and lists every shown value.
3. Wait for the state square to show saved and for the page to be measured, then choose **Take away → HTML**. The measurement now covers the opening and every declared static state, so the check also fails when only the static state overflows, clips or loses contrast. Expected: the file opens on the static state in the reading and presentation views. Without JavaScript it draws the frozen state:
   - a chart: the frozen selection (and focus), the value line and **View all data** with the complete table. Since S4 the value line also states the filter ("Filter: author order, A → B (n of N categories)") and, for a value-sorted chart, the sort and each shown category's rank among all of them, so non-adjacent ranks are never read as the top N; both views draw the chart at the same size;
   - a diagram or code step: the step's node, relationship and both ends, or its source lines, are marked, and a line gives the step's label, text and location;
   - a comparison tab: the chosen image stays in place, the other one sits in a closed **First original image** / **Second original image** disclosure;
   - hotspots: numbered markers at the authored positions, the open one outlined, and a line with its annotation and original-image coordinates. Every annotation block stays on the page.
4. **Replay cue sequence** still starts from the authored opening and plays every cue. Exploring hides the value line until the scene is back at the static state.
5. For a static fallback under reduced motion, set `"reducedMotion": "static"` in the scene's `motion` in **More → For developers → Data editors → Authored interactions, cue order and motion · JSON**. Expected: with the system reduced-motion setting on, the scene shows its static state, **Replay cue sequence** is disabled and a notice says cues do not play. **Next cue** and the slider still work. With `"instant"` (the default) cues play without animation, as before.
6. **Lock this page** also keeps the static state: the control is disabled and a save that changes it is refused. Clear the lock first.
7. **Use current chart / step as opening** refuses to copy the static state the preview opens on (see step 5 above). Explore first, or move **Cue position** to 0.
8. Without a static state nothing changes: the reader without JavaScript sees the complete authored data and the player opens at the authored opening (decision C7). To freeze the opening itself without JavaScript, declare a key state at position 0 and choose it here.
9. Recovery: **Authored opening (default)** removes the static state; it is refused while `reducedMotion` is `static`, so set it to `instant` first. If the measured check fails only after you chose a static state, the frozen view itself does not fit (for example a long value line at 390 px); choose another key state or shorten the content, then wait for the measurement again. `STATIC_STATE_UNIMPLEMENTED` no longer exists; an older build that still answers it cannot draw frozen steps, comparisons or hotspots. Undo restores the previous choice.

## Focus one series or hide it

A chart keeps separate pieces of state: dataset, metric, shown series, focused series, category range, order, scale and the explanation's subject. Focusing and hiding are different actions with different results. [Evidence](../evidence/s5-motion-state/review.md).

1. **Focus:** with a series name emphasises that series. Expected: every other shown series stays drawn, with its values and legend entry. On a line, grouped bar, dot-and-interval chart or small multiples the focused series is drawn as a declared focus (its legend entry ends with **· Focus**, the others are lighter); on an area, stacked or scatter chart the other series take a lighter version of their own colour (never below 3:1 against the page). The button is pressed; the status line ends with **Focus: <series>**; the explanation line under the chart gives only the focused series' value. **No focus** returns to equal emphasis; when the chart declares its own focus the button reads **Author's focus** and returns to it.
2. **Show:** checkboxes hide or show whole series. Expected: a hidden series leaves the marks, the legend and **View selected data**; its values keep their anchors in **Full original dataset (unfiltered)**; the remaining series keep their colours. Hiding the focused series ends the focus. A hidden series cannot be focused: its focus button is disabled until you show it again.
3. The explanation line follows the focus: on a ranked bar it describes the top rank of the current range, on other charts the last category in range (the latest, for time), for the focused series or for every shown series.
4. To keep a focus, choose **Use current chart / step as opening** (it stores `initialFocusSeriesId`), or add a `data.focus` cue in the interaction JSON: `{"id":"focus-a","event":"data.focus","interactionId":"…","seriesId":"a","label":"…"}`; leave out `seriesId` to clear the focus. A key state at that cue can be the static state; static output then draws the focus and its value line ends with **Focus: <series>.**
5. Heatmaps have no series focus (their colour encodes sign); hide rows instead. A single-series chart has no series to focus or hide: it shows no **Show:** or **Focus:** controls, and its emphasis is a category focus declared on the chart (`focus: {categoryIds: […]}`). A `data.focus` cue or `initialFocusSeriesId` on a single-series chart is refused with **A single-series chart cannot focus a series**.
6. The layered focus rule (decided in S6). A chart's declared `focus` (categories or series) is the author's default emphasis and is what readers without JavaScript see. A reader's focus overrides it while it is set; **Author's focus** returns to it. A static state that freezes a `data.focus` cue is a reader focus, so static output draws that series rather than the declared focus. Facts never change: the complete table is identical in every case.
7. Recovery: **Focus not applied: Show a series before focusing it** means the series is hidden; tick it under **Show:** first. A plan whose `data.focus` cue or `initialFocusSeriesId` names a hidden series is refused when the preview is built; show the series in the cue before it, or change the focus.

## Cue clock, motion and keyboard

1. One clock per scene drives **Replay cue sequence**, **Play cues** / **Pause cues**, **Previous cue**, **Next cue**, the slider and the reduced-motion fallback. Expected: at most one cue timer is pending per scene; pausing, seeking, exploring, leaving the scene or hiding the tab cancels it together with running animations and registered resources.
2. Motion uses six named primitives on the existing cue events. Each animates from a nearly final state to the final one, so reduced motion, a cancelled animation or a browser without the Web Animations API shows the final content directly.

| Primitive | Cue events | What moves | With reduced motion |
| --- | --- | --- | --- |
| FadeIn | `data.focus`, `step.next`, `step.select` | marks of the focused series; the highlighted node, relationship or code line | content directly visible |
| SlideSmall | scene entry and replay, `data.filter`, `data.focus` | scene regions; the current chart view after a range change; the explanation line | content directly visible |
| Crossfade | `tab.select` | the comparison panel, already in its new layout | target layout entered directly |
| RevealMask | `step.next`, `step.select` | the step explanation panel, revealed from its reading edge | full graphic and explanation shown |
| SeriesReveal | `data.filter` showing a series | marks of each newly shown series, one after another; axes, units and baseline stay still | full graphic shown |
| AnnotationReveal | `annotation.reveal` | the hotspot explanation panel | full annotation shown |

   Durations stay within 400 ms (FadeIn and SlideSmall within 220 ms). The handoff's proposed 450–800 ms for mask, series and annotation reveals is not adopted.
3. In presentation view, ArrowLeft/ArrowRight turn the page only when no control has focus. Expected: with a slider, select, checkbox, button, link, disclosure, tab, scrollable code block or chart mark focused, arrow keys, Home/End, Space and Enter change that control or do nothing; the page number stays. Keys with Alt, Ctrl, Cmd or Shift never turn the page.
4. Recovery: if the page does not turn, move focus off the control first (Tab past it, or click empty page space), then press the arrow key, or click the right or left half of the slide; a translucent key shows the direction. The two keys are also reachable with Tab.

## Explain → Diagram → Explore (blueprint A, S9b)

One page explains one object in three stages. It is a `steps` interaction over a diagram with a `blueprint` declaration: the page's heading is the question, a paragraph or callout is the short answer, the diagram nodes are the parts and one explanation describes the whole object. The cue clock is the stage clock. [Evidence](../evidence/s9b-blueprint-a/review.md) · [Studio steps](visual-studio.md#explain--diagram--explore-pages-s9b).

| Stage | Cue position | What the page shows | What the reader can do |
|---|---|---|---|
| Explain | 0 | The question, the short answer and the object's name. The diagram is not drawn yet. | **Next stage**, **Previous stage** (disabled here), **Skip to the complete explanation** |
| Diagram | 1 | The whole object with every part label and its reading-order number, and the whole object's explanation | Select a part (on the diagram or with its button), **Show whole** |
| Explore | 2 and later | One part against the whole: the part is marked and the other parts stay drawn; the panel gives the part, the whole object's explanation and the parts before and after it | Part buttons, the diagram's parts, arrow keys, **Show whole**, **Previous stage** / **Next stage** |
| Static | the author's choice | The complete explanation, with no action: the whole object, numbered parts and every explanation as text | — |

1. Open the exported HTML and go to the blueprint page. Expected: the page opens on **Explain** even when its static state is Diagram; the stage pills read *Explain · Diagram · Explore* with *Explain* marked and the count reads *Explain · 0 / n*.
2. Choose **Next stage**. Expected: the diagram appears with numbered parts, the panel names the whole object and lists the reading order. Each further **Next stage** explores the next part in reading order; the last part stays.
3. Select a part: click it on the diagram, or click its numbered button. Expected: the part is marked, the other parts stay visible (lighter outline), the panel reads *Part k of n · …* with the whole object and the parts before and after it. The count starts with *Exploring ·*. **Show whole** returns to Diagram, never to Explain.
4. **Restore rule (A, per-page memory).** Turn the page by clicking the right half of the slide and come back by clicking the left half, or with the arrow keys. Expected: the page shows the same stage and part you left, still marked *Exploring*. The memory lasts while the document is open; **reload** opens the page on Explain again. Leaving the page stops its cue timer and animations, and keeps the selection.
5. **Keyboard.** Tab to a part on the diagram or to a part button. Arrow keys (left/right and up/down), Home, End, Enter and Space change the part. Enter or Space on **Next stage**, **Previous stage**, **Show whole**, **Skip** and **Replay from Explain**, and the arrow keys, Home and End on the cue slider, change the stage. Expected: none of these ever turns the page. With nothing focused (click empty page space), ArrowRight and ArrowLeft turn the page as before.
6. **Skip to the complete explanation** jumps to the author's static state (Diagram when none is declared).
7. **Reduced motion.** With the system reduced-motion setting on, every stage changes instantly and Next / Previous still reach every stage. With `"reducedMotion": "static"` the page opens on its static state, **Replay** is disabled and a notice says cues do not play; Next, Previous and the slider still reach Explain and every part.
8. **Without JavaScript, and in PowerPoint and PDF**, a blueprint page always shows the complete explanation: the whole object with numbered parts, the whole object's explanation and every part's explanation in reading order. With a static state, a line starts with **Static view** and names it; an Explore state marks its part. PowerPoint receives the parts as shapes with native number circles and the explanations as a native numbered list.
9. **Export refusal.** PowerPoint and PDF refuse a blueprint page without a static state (`BLUEPRINT_STATIC_REQUIRED`) or with Explain as its static state (`BLUEPRINT_STATIC_INCOMPLETE`): the message names the page. The static-state stage of the export order also refuses a measured page that lacks a part label or an explanation. HTML export is not refused: its no-JavaScript view is complete.

Recovery:

- *Page …: Choose the static state…*: choose Diagram or an Explore state under **Still picture for print**, wait for the autosave and the measurement, export again.
- *A blueprint A page always opens on Explain* when choosing **Use current chart / step as opening**: the opening is fixed; choose the static state instead.
- A plan that names a relationship as a part, explains a part twice, adds a second interaction, sets `initialStepId`, has more stage cues than parts plus one, or hides the question, answer or diagram behind a disclosure is refused when the preview is built (`INVALID_INTERACTION`; see `tests/fixtures/visual/s9b.negative.json`).
- No parameter control exists: Explore compares a part with the whole statically (alignment §17, answer 5).

## Author and save the behavior

1. Under **More → For developers → Data editors**, edit the closed JSON object **Authored interactions, cue order and motion**: `interactions`, ordered `cues`, and optional `motion`. Edit the separate **Semantic explanation content** field for labels, original explanation text and source references; the scene plan stores only stable explanation identities, not copies of those facts. Keep stable identities. Preview errors retain the edited project; invalid JSON remains in an unapplied draft until repaired or explicitly discarded.
2. Wait for measurement and autosave. The project records the author's configuration. Audience filters, focus, selected tabs, revealed hotspots and current step never write back to project data or revision history. Measurement temporarily checks the authored initial state and each declared static state, then restores the explored view; filtering cannot replace the source receipt with a smaller audience view.
3. Use **Lock this page** to protect `interactions`, `cues` and `motion`. It also holds the page's theme and composition; the API can lock them separately. Content locks also protect attached interaction definitions and cues, including comparison partners and hotspot annotations. Viewers may still explore those components; they do not edit author content.
4. After a save conflict, retain Project JSON and reopen the current revision. **More → Earlier versions** opens read-only snapshots; restore creates a separate copy. Reordering scenes or selecting composition candidates keeps scene/block/object/series/step identities. Old v1/v2 projects remain on their existing path, with explicit copy migration.

## Contract and limits

Scene interaction kinds are `chart-select`, `image-compare`, `image-hotspots` and `steps` (a `steps` interaction over a diagram may declare `blueprint {questionBlockId, answerBlockId, wholeExplanationId}`, S9b). They target existing same-scene blocks. Chart selection requires explicitly authored `categoryIds`; names or array positions never become inferred identities. Series keep their original palette identity when another series is hidden. A one-category range remains a real observation or missing value, with no invented adjacent points. Reordering/removing categories may invalidate a saved range or cue; repair it explicitly rather than accepting a guessed substitute.

Comparison uses two existing image blocks and their existing local assets/crops; neither original is replaced. Hotspots use stable `id`, normalized original-image `x`/`y`, and an existing same-scene `annotationId`. Out-of-crop hotspots fail validation; explicit contain slots account for letterboxing. Crop/source changes are validated against these coordinates. Touch target placement may be inset to keep the full button operable at an edge; the displayed original coordinates remain exact.

Steps contain stable `id`, a semantic `explanationId`, and either a supplied diagram `objectId` or original code `lines`. Code line references are authored source line numbers; explicitly revise them when inserting/reordering source lines. All code text remains escaped and never executes.

The event vocabulary includes `scene.enter`, `scene.exit`, `step.next`, `tab.select`, `data.filter`, `data.focus` and `annotation.reveal`. A chart selection may declare `initialFocusSeriesId` (a series shown at the opening). Scene entry/exit are lifecycle events; authored cue arrays contain bounded data/step/tab/annotation actions. Replay and seeking use a pure reducer. This is cue-boundary sequencing, not a video-frame editor. Motion supports only the six finite primitives above (0–400ms), with no unsolicited autoplay. The optional resource-disposal hook is not evidence of a native 3D/media host integration; v3 itself allocates no WebGL renderer or external media stream.

HTML embeds the fixed runtime and inert, escaped interaction data under its hash-based CSP. It requests no runtime package, remote service, image provider or telemetry endpoint. Project JSON retains the editable content and author interaction plan; bare Presentation JSON contains semantic content only. Native v3 PowerPoint/Figma/AE compilers remain explicitly unsupported; they are not made editable by rasterizing a slide.
