# Semantic interaction and replay

[简体中文](../zh-CN/interactions.md) · [Components](components.md) · [Evidence](../evidence/vis-009/review.md)

## Apply to an existing work

1. Open your saved work in Visual Studio. Choose a page, **Edit page → Content → Scene interactions and motion → Add explanations to this page**. This adds selection controls to existing charts and steps to existing diagrams; it creates no new deck or page. Existing interactions stay intact. Locked content must be unlocked explicitly first.
2. Charts without category identities receive new stable identities once, as part of this explicit action. Values, order and units stay intact. Use **All series**, a named series, checkboxes and the category range to change the actual chart. The legend, selected-data table, range explanation and last-category values use the same selection. The full original dataset remains available.
3. Edit the step labels and explanation fields. New diagram steps reference supplied edge identities when every edge has one; otherwise they reference existing nodes. Initial text uses only supplied labels/notes. Selecting an edge highlights it and its endpoints together with the explanation. Author fuller explanations in these fields as needed.
4. Set **Page transition motion** to **Subtle**, **Off** or **Follow theme**. Global Motion Off and system/user Reduce motion take precedence. Finite transitions follow the selected chart/step; replay and Next cue use the same state reducer.
5. Explore the chart or step in the preview, then choose **Use current chart / step as opening** to retain that choice. Save, wait for the measured preview and export HTML. Reopen and offline HTML start from that authored selection. Temporary audience exploration stays transient. The opening action does not change image comparisons/hotspots or the authored cue order.
6. If the preview rejects a plan or export is disabled, repair unapplied JSON/fit errors first. Undo restores the previous author state; Project JSON retains a backup. Workbench projects continue to require their existing image review before export. Native v3 PowerPoint/Figma/AE compilers remain unavailable.

The optional interaction examples below exercise the same editor and runtime.

1. Run `npm run studio:interactions` with Node 22 or newer. Open the printed loopback `/visual` address. Choose an English or Chinese story in Library. Another library can use **Interactive examples**. Each 15-page story retains the existing four-page material and exact component examples.
2. Select a chart page. Use **From category**, **To category** and the series checkboxes. Marks, labels, legend and selected-data table change together. **Full original dataset (unfiltered)** keeps the original order, values, nulls, units and time instants. Unchecking the last series or reversing the category range is refused; the previous valid selection remains.
3. Select the image comparison page. Choose **First image**, **Second image** or **Compare both**. The actual image view changes, including its authored crop and alternative text. Arrow Left/Right and Home/End select tabs. The example compares two authored crops of one local illustration; it makes no historical before/after claim.
4. On the image narrative page, activate a numbered hotspot. Its source-bound annotation and original-image coordinates appear. Activate it again to collapse the explanation. All original annotation text remains on the page.
5. On diagram/code pages, choose an explanation step. A diagram shows the supplied node or directed relationship and authored explanation. Code shows the original referenced lines in a separate excerpt, with their line numbers; the complete original code, whitespace, emphasis and source anchor stay intact above it. Arrow keys and Home/End also move between step buttons.
6. Choose **Replay cue sequence** to reset and play the authored cue order, one cue per second. **Pause cues** stops at the current boundary. **Next cue** or the cue-position slider selects a deterministic prefix from the authored initial state. Native keyboard Home/End and arrows operate the slider. Manual exploration is temporary; replay/seek recomputes the authored sequence independently of it.
7. **Reduce motion** removes visual animation while leaving all controls, explanations and cue playback functional. An operating-system reduction preference cannot be overridden by the page. The author's global motion **Off** also wins over an individual scene's subtle motion. Switching scenes or browser tabs stops that scene's cue timer and finite animations; it retains the current information state. Replay or Next cue can continue after returning.

Mouse, keyboard and touch use the same semantic actions. Controls have native focus behavior and at least 44px touch targets. No-JavaScript reading shows complete original graphics/data/code, both source images and expandable authored explanations/cue order. A scene with a declared static state shows its frozen chart selection instead, with a text line of the shown values and the complete table. Reading mode permits local horizontal scrolling for large charts, diagrams or exact code. Print requests show static content without playback controls. Actual screen-reader, real IME and broader print/application acceptance remain separate gates.

## Freeze a static state

A static state is the key state that exported files without JavaScript show, that the player opens on, and that reduced motion falls back to. [Evidence](../evidence/s2-vertical-sample/review.md) · [Known conflicts](../plans/design-handoff-vertical-sample.md#conflict-list).

1. Key states come from the project JSON (`keyStates` on a scene: an `id`, a cue `position` and an optional `label`; 0 is the authored opening). Studio cannot create them yet. To use them, import the project with **Import and examples → Import visual JSON**.
2. Open the page and choose **Edit page → Content → Scene interactions and motion**. Next to **Use current chart / step as opening**, set **Static state for export and reduced motion** to a key state, for example `1 · Structure-first habits (3 of 6)`. Expected: the preview shows that selection, the cue position reads `1 / 2`, and a line above the chart starts with **Static view** and lists every shown value.
3. Save and wait for **✓ Fonts, images and DOM layout measured in this browser**, then choose **Export HTML**. Expected: the file opens on the static state in the reading and presentation views. Without JavaScript it draws the frozen selection, the value line and **View all data** with the complete table.
4. **Replay cue sequence** still starts from the authored opening and plays every cue. Exploring hides the value line until the scene is back at the static state.
5. For a static fallback under reduced motion, set `"reducedMotion": "static"` in the scene's `motion` in **Authored interactions, cue order and motion · JSON**. Expected: with the system setting or **Reduce motion** on, the scene shows its static state, **Replay cue sequence** is disabled and a notice says cues do not play. **Next cue** and the slider still work. With `"instant"` (the default) cues play without animation, as before.
6. **Lock this scene interaction plan** also keeps the static state: the control is disabled and a save that changes it is refused. Clear the lock first.
7. Recovery: **Authored opening (default)** removes the static state; it is refused while `reducedMotion` is `static`, so set it to `instant` first. If export answers `STATIC_STATE_UNIMPLEMENTED`, the chosen key state changes a step, comparison or hotspot, which static output cannot draw yet; choose a key state that changes only chart selections, or the opening. Undo restores the previous choice.

## Author and save the behavior

1. In **Content**, expand **Scene interactions and motion**. Edit its closed JSON object: `interactions`, ordered `cues`, and optional `motion`. Edit the separate **Semantic explanation content** field for labels, original explanation text and source references; the scene plan stores only stable explanation identities, not copies of those facts. Keep stable identities. Preview errors retain the edited project; invalid JSON remains in an unapplied draft until repaired or explicitly discarded.
2. Wait for measurement, then Save. The project records the author's configuration. Audience filters, selected tabs, revealed hotspots and current step never write back to project data or revision history. Measurement temporarily checks the authored initial state and restores the explored view; filtering cannot replace the source receipt with a smaller audience view.
3. Use **Lock this scene interaction plan** to protect `interactions`, `cues` and `motion`. This is independent of the theme/composition lock. Content locks also protect attached interaction definitions and cues, including comparison partners and hotspot annotations. Viewers may still explore those components; they do not edit author content.
4. After a save conflict, retain Project JSON and reopen the current revision. **History** opens read-only snapshots; restore creates a separate copy. Reordering scenes or selecting composition candidates keeps scene/block/object/series/step identities. Old v1/v2 projects remain on their existing path, with explicit copy migration.

## Contract and limits

Scene interaction kinds are `chart-select`, `image-compare`, `image-hotspots` and `steps`. They target existing same-scene blocks. Chart selection requires explicitly authored `categoryIds`; names or array positions never become inferred identities. Series keep their original palette identity when another series is hidden. A one-category range remains a real observation or missing value, with no invented adjacent points. Reordering/removing categories may invalidate a saved range or cue; repair it explicitly rather than accepting a guessed substitute.

Comparison uses two existing image blocks and their existing local assets/crops; neither original is replaced. Hotspots use stable `id`, normalized original-image `x`/`y`, and an existing same-scene `annotationId`. Out-of-crop hotspots fail validation; explicit contain slots account for letterboxing. Crop/source changes are validated against these coordinates. Touch target placement may be inset to keep the full button operable at an edge; the displayed original coordinates remain exact.

Steps contain stable `id`, a semantic `explanationId`, and either a supplied diagram `objectId` or original code `lines`. Code line references are authored source line numbers; explicitly revise them when inserting/reordering source lines. All code text remains escaped and never executes.

The event vocabulary includes `scene.enter`, `scene.exit`, `step.next`, `tab.select`, `data.filter` and `annotation.reveal`. Scene entry/exit are lifecycle events; authored cue arrays contain bounded data/step/tab/annotation actions. Replay and seeking use a pure reducer. This is cue-boundary sequencing, not a video-frame editor. Motion supports only finite subtle fades/translations (0–400ms), with no unsolicited autoplay. The optional resource-disposal hook is not evidence of a native 3D/media host integration; v3 itself allocates no WebGL renderer or external media stream.

HTML embeds the fixed runtime and inert, escaped interaction data under its hash-based CSP. It requests no runtime package, remote service, image provider or telemetry endpoint. Project JSON retains the editable content and author interaction plan; bare Presentation JSON contains semantic content only. Native v3 PowerPoint/Figma/AE compilers remain explicitly unsupported; they are not made editable by rasterizing a slide.
